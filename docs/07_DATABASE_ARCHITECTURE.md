# 07. Database Architecture

We use PostgreSQL hosted on Supabase. Row Level Security (RLS) is paramount to ensure multi-tenant security.

## Core Entities

### `users` (managed by Supabase Auth)
- Links to standard Supabase auth.users.

### `stores`
- Represents a tenant (a Shopify store).
- `id` (UUID), `user_id` (FK), `name`, `shopify_domain`, `shopify_access_token`, `meta_access_token`, `created_at`.

### `products`
- Synced from Shopify.
- `id`, `store_id` (FK), `shopify_product_id`, `title`, `inventory_level`, `price`.

### `orders`
- Synced from Shopify.
- `id`, `store_id` (FK), `shopify_order_id`, `total_price`, `created_at`.

### `ad_campaigns`
- Synced from Meta.
- `id`, `store_id` (FK), `meta_campaign_id`, `name`, `spend`, `roas`, `status`, `date_synced`.

### `alerts`
- Output of the Rule Engine.
- `id` (UUID)
- `store_id` (FK)
- `rule_id` (String identifier for the rule triggered)
- `raw_data` (JSONB - the facts that triggered the rule)
- `ai_explanation` (Text - generated by OpenAI)
- `ai_recommendation` (Text - generated by OpenAI)
- `status` (Enum: 'new', 'read', 'resolved', 'dismissed')
- `created_at`

## Security Model
- **RLS Enabled:** Every table MUST have Row Level Security enabled.
- **Policy:** `store_id = current_store_id()` or `user_id = auth.uid()`.
- Tenants can never read cross-tenant data.
